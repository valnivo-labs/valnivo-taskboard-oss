# Changelog

- Git: a signed forge webhook (GitHub, GitLab, Gitea) links commits and pull requests to tasks, moves a task to review when a PR opens and closes it when the PR merges (respecting the definition of done), and reports requested changes and failed CI.
- Cost: agents report tokens and USD per task (`cost`, or `cost` on `finish`); per-agent, task, board and day reports; monthly board and task budgets warn the supervisor.
- Wake-ups: signed pings to agents that have work waiting but are silent, with backoff and escalation; heartbeats extend a claim; `runner.py` runs a command per task for an agent.
- Cross-board dependencies in the task dialog (search any board), `links`, an attention item for work waiting on another board, and bulk move (`move_tasks`, bulk bar).
- Chat channels for humans: Slack, Discord, Teams, Telegram or generic JSON for blocked, done, escalations, sprints, budgets and git events.
- Browser end-to-end tests (`make e2e`, a CI job); reloading many times no longer loses data (the shared database connection is serialised, errors answer 500 instead of dropping the connection, larger listen backlog, client retries).
## Unreleased
- Stuck-work digest: `GET /api/digest/stuck` and the `stuck_digest` tool list cards stuck in review, approved, deploying, blocked or in progress beyond thresholds (owner, hours, who they wait on), the oldest unanswered review requests and overloaded agents, as counts and ids only (supervisor or admin; System has a card). With the setting `digest_cfg` (e.g. `{"times": ["09:00", "14:00"], "days": "mon-fri", "tz": "Europe/Paris"}`) the server sends one quiet digest per slot to the supervisors; nothing is sent until slots are configured.
- Fewer wasted tokens, all opt-in settings: a review SLA (`review_sla_min`: one nudge to the reviewer after that many idle minutes in working hours, one escalation after a second window, re-armed by any activity), inbox hygiene (`fyi_expire_h`: old FYI and automated notices are marked read, assignments, review requests, asks and messages from people are kept), a soft warning when an agent reads the same task three times in two minutes (`refetch_warn=1`, counted in the usage report) and `finish` accepting `in`, `out`, `cached` token counts.
- Agent workload: `GET /api/workload` and the `workload` tool rate each agent idle, ok, busy or overloaded (open work against capacity, reviews waiting on them, blocked, stale and overdue cards, unread actionable inbox, 7-day throughput, failed runs) with the reasons and a suggested action. Supervisors and admins see everyone, others only themselves; System has a card with drill-down, the supervisor briefing carries one line of names, and a newly overloaded agent is reported once per 24 hours as a quiet inbox item. Thresholds: setting `workload_cfg` (JSON).
- Optional task lifecycle with deploy states (board setting `ship`): review > approved > deploying > verified > done, no skipped steps, a deploy owner and due time when a card is approved, health check, smoke test and rollback sha required for verified, and finish on such a board goes to review. Reminder and escalation for a card stuck in approved, counted in working hours (settings `work_start`, `work_end`, `work_tz`). Off by default; boards without `ship` keep their flow (approved is an optional extra step).
- Safety and proof: acceptance lines that start `check:` (`tests_green`, `required_fields`, `output_field`, `pr_linked`) are tested by the server when work is finished; a note and proof per criterion (`evidence`, `finish met=[{n,note,ref}]`); a secret guard that redacts or refuses keys and passwords in text; idempotency keys (`Idempotency-Key`) so a retry never does a call twice; limits on how big one story or epic can grow; lease fencing (`lt`) so a holder whose claim was taken over cannot write; and `self_assign_only` and `evidence_before_review` rules for the strict way of working.
- Collaboration: agents `propose` work and a supervisor accepts or declines it; `lesson` candidates cool down and are promoted into the board's rules by a person; `wait` records who a task is waiting for and why (long waits go to the supervisors); `route` explains its scores and agents have a role and goal; boards can save their own task sets with dependencies.
- Operations: new machines can wait for admission (`admit_node`), a nearly full disk opens one ops task per machine and tier, a read-only snapshot of the boards is written every five minutes, chat commands (`POST /api/intake`: new, status, note, done, assign) run as a mapped person with the message id as the idempotency key, System lists data-quality checks, and events say which bridge an action ran for.
- Choose how strict the way of working is, per board: **loose** (move work freely), **standard** (allowed paths and acceptance written before work starts), **strict** (also one holder, claim to start, an independent check before done, everything under a story) or **custom** (switch single rules). A task can ask for more discipline than its board (`rg`); only a supervisor can lower it. New stories can start with the board's own pipeline. Owner, admin or supervisor set it (Board settings, `set_policy`); agents read the rules with `policy`, and a refused call says which rule applied.
- Fewer tokens between agents: a one-paragraph **state of play** per task (kept by `finish` and `handoff`, shown in every brief), reads that return **only what changed** (`task since=<ev>`), `say kind=fyi|ack` and `comment quiet` that never wake anyone, a role-based default tool set on the connector (core for agents, core+coord for supervisors), and a per-day record of tokens each agent spends talking to the board (System → Tokens spent).
- Better collaboration: story scaffolds (`scaffold`: standard, bugfix, research), a short **decision log** on epics and stories that every task below sees, **needs / produces** on tasks, an automatic **independent check** request (`verify_queue`, `verify.requested`) to the best free agent, answered questions offered before asking again (`faq`, `sim` on `ask`), routing that prefers whoever finished similar work (`fit`), and overlap warnings for two open tasks on one pull request or `area:` label.
- Work nests as epic > story > task (or bug, spike, chore): a story sits under an epic and can hold tasks, a task can sit under a story or straight under an epic, and only epics and stories can have children. Progress rolls up through the levels (done/total of the work items below), a story or epic is told when everything under it is done, moving an epic or story carries its whole tree, and the dialog has "+ Add a task under this" and type templates (story, bug, spike, epic).
- Before and after on every change: each task event now carries the earlier value of what changed, the timeline shows "priority 3 -> 1", and `history {id}` replays a task's events and compares them with the card (in sync, partial for values older than the log, or drift).
- Strict moves (setting `strict_moves=1`, Admin → Budgets): a task only moves along the allowed paths; a supervisor or admin can override with `force`.
- Pipelines: a task can carry ordered stages (`pl`: name | holder | auto, review or human). `stage` starts it, the holder passes the baton on, a review stage can send it back one stage with a reason, and a human stage parks the task until that person approves or sends it back. Past the last stage the task is done.

- Tamper-evident history: every audit event is chained to the one before it, so an edited or removed event is found (`audit_verify`, Admin → Audit log). Optional setting `holder_only=1`: a task someone currently holds can only be changed by that holder, a supervisor or an admin.
